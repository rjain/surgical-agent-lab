Before You Arrive

Run these steps in the week before the workshop, so your laptop, network and key are confirmed working. About ten minutes, and one report to send back.

Installed already: Python 3.12 or newer, git, and Antigravity. Everything else is below. If any of those are unavailable on your machine, please let us know this week. Monday 7 September is a holiday, so Friday is the last working day before the session.

Step 1 get the repo and install it

macOS / Linux

git clone https://github.com/rjain/surgical-agent-lab.git cd surgical-agent-lab python3 -m venv .venv source .venv/bin/activate pip install -r requirements.txt

Windows (PowerShell)

git clone https://github.com/rjain/surgical-agent-lab.git cd surgical-agent-lab python -m venv .venv .\.venv\Scripts\Activate.ps1 pip install -r requirements.txt

Keep the environment active for the steps below.

Step 2 fetch the dataset

python -m lab.get_data

335 KB from the published SurgVU release; expect 155 cases, 310 CSV files. Labels only: task segments and instrument logs. You never need the video.

Step 3 add your API key

python -m lab.set_key

Paste the key we sent you. The prompt is hidden, so the key stays out of your screen and your shell history, and .env is written readable only by you.

The two rules about the key

Never paste it into the Antigravity agent chat. The agent already reads your workspace, and pasted secrets end up in transcripts and commits.

Never put it in the repository, a screenshot, or on a shared screen. If it is exposed, tell us. Reissuing takes seconds.

No key yet? Skip this step. Everything else still verifies; re-run Step 5 when the key arrives.

On the day, run git pull first. We refresh one file in the repository on the morning of the session. It takes a second and we will say so at the start, but it is worth knowing now.

Step 4 open it in Antigravity

Antigravity is the IDE for the session. File → Open Folder on surgical-agent-lab, then four things worth knowing:

  • Click Trust when the banner appears. A fresh clone opens in Restricted Mode, which disables the debugger and the run targets, so if Run and Debug does nothing, this is why. Also at File → Trust Folder.
  • Accept the three recommended extensions. If you are not prompted, install them from the Extensions panel: ms-python.python, ms-python.debugpy (the run targets need it) and detachhead.basedpyright (completions). Do not go looking for Pylance. Antigravity installs from Open VSX, and Pylance is not published there. basedpyright does that job here.
  • Sign in with your own Google account. We do not issue an Antigravity login. The API key is not a login: it sits in .env and is what your code uses to call Gemini.
  • Create the environment before you open the folder, or reload the window afterwards. If the interpreter is not picked up, run Python: Select Interpreter and choose .venv.

Step 5 run pre-flight and send us the result

python preflight.py

Copy everything below the dashed line and send it back. Eleven checks, none of them billed. The one API call lists available models, which is free and still proves your network reaches Google, that TLS inspection has not broken the SDK, and that your key works.

python 3.12.4 platform macOS-15.5-arm64 PASS Python version 3.12.4 PASS Virtual environment .venv PASS Required packages streamlit 1.62.0 PASS Gemini API key set, 53 chars, ending WWdg PASS API reachable 54 models listed, gemini-flash-latest among them PASS Dataset readable 155 cases under ./data/labels PASS Detection pipeline case_045: 4 flags PASS Port 8501 free Streamlit can start PASS Antigravity extensions all 3 present WARN Lab clips visible this key cannot read the lab's clips SKIP Generation (billed) instructors: pass --spend to run this 9 passed, 0 failed, 1 needing attention, 1 skipped

The SKIP is an instructor-only billed check, and the WARN on lab clips is expected before the day — the session's clips are refreshed on the morning. Both are fine to send as-is.

Without a key, the key line reads WARN, the line below it SKIP, and pre-flight still reports Setup is correct. Your machine is verified and only the key is outstanding.

If a check fails

Each failure prints the fix on the line beneath it. Send us the report either way. There is no need to spend more than five minutes on it; sorting these out is our job, not yours.

What you seeWhat it means
FAIL API reachable: API key not valid A truncated paste, stray quotes, or a revoked key. Re-run python -m lab.set_key and paste it again.
FAIL API reachable: timeout or certificate error Corporate proxy or TLS inspection. The one we most need to know about early, and cannot fix from our side. Send the exact error.
FAIL Dataset readable Step 2 did not run, or ran in a different folder. Re-run python -m lab.get_data from the repository root.
WARN Antigravity extensions: N missing Step 4; it names which ones. Not a blocker; everything in the lab also runs from a terminal.
FAIL Port 8501 free Something else is using it. Quit it, or tell us and we will move the interface to another port on the day.
FAIL Required packages The install did not finish, or the environment is not active. Re-run pip install -r requirements.txt with .venv active.

Optional if you want to look around first

pytest -q # 79 tests, no key needed, no tokens spent streamlit run ui/app.py # the interface, on http://localhost:8501

Both run without a key: the detection layer uses no model at all, which turns out to be the point of the first block. lab/rules.py is worth a read beforehand if you are curious. Nothing else needs preparing.

What you are building, in one line

A review tool for recorded surgical training exercise footage: it finds the moments worth discussing, asks Gemini what those moments look like, and puts an agent over both. It is an educational exercise and not a medical device: no diagnosis, no patients, no clinical use.
